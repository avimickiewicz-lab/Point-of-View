# Point of view — мобильный веб-макет

Веб-версия Android-приложения (`app/…/MainActivity.kt`):
превью камеры → снимок → сохранение в галерею → **распознавание Брайля** моделью YOLO26 (`braile.onnx`)
прямо в браузере. Перевод между стандартами (ИИ-агент) будет подключаться к разделу «Перевод».

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | Разметка: видоискатель, нижняя панель (кнопка съёмки + меню), галерея, просмотр |
| `styles.css` | Стили, мобильная вёрстка, safe-area для iPhone |
| `app.js` | Камера (`getUserMedia`), съёмка, галерея (IndexedDB), сохранение на устройство, раздел «Распознать» |
| `braille.js` | Подготовка изображения для модели, разбор выхода YOLO, NMS, сборка строк и текста |
| `recognizer.js` | Загрузка `braile.onnx` и запуск через ONNX Runtime Web (WebGPU, иначе WASM) |
| `standards.js` | Стандарты Брайля и обратный перевод: русский и английский — liblouis, китайский — `zh.js` |
| `zh.js` | Китайский Брайль (现行盲文) → пиньинь с тонами → иероглифы по словарю |
| `i18n.js` | Язык интерфейса (русский / английский): все тексты интерфейса и подписи |
| `agent.js` | ИИ-агент в браузере: исправление и перевод RU ↔ EN (режимы «выкл / на устройстве / сервер») |
| `corrector.js` | Исправление на устройстве: словарь + замена клеток, отличающихся одной точкой |
| `agent/agent.py` | Сервер агента (stdlib Python): Claude API или OpenAI-совместимый (Ollama); подключён к `serve.py` |
| `agent/config.*.example.json` | Образцы настроек агента; рабочий `agent/config.json` не попадает в git |
| `data/words-ru.txt.gz`, `data/words-en.txt.gz` | Частотные словари (150 тыс. / 80 тыс. слов, FrequencyWords, CC BY-SA 4.0) |
| `vendor/liblouis/` | liblouis 3.39.0 (сборка JS из `liblouis/js-build`, LGPL-2.1) и нужные таблицы |
| `data/zh-dict.json.gz` | Словарь для подбора иероглифов (~82 тыс. слов, jieba + pinyin-data, MIT); `build_zh_dict.py` — сборка |
| `models/braile.onnx` | Модель YOLO26 (копия `app/src/main/assets/braile.onnx`) |
| `manifest.webmanifest`, `sw.js`, `icons/` | PWA: установка на главный экран, офлайн-оболочка |
| `serve.py` | Локальный сервер: файлы приложения + API агента `/api/agent` |

## Интерфейс

- **Видоискатель** на весь экран над панелью, рамка-прицел для текста Брайля, фонарик (если камера его поддерживает).
- **Нижняя панель** (`.dock`):
  - ряд управления — миниатюра последнего снимка (открывает галерею), **кнопка съёмки** по центру, переключение камеры;
  - **меню приложения** (`<nav class="menu">`) — зарезервированные разделы: Камера, Распознать, Перевод, История, Настройки. Неготовые помечены `data-soon`.
  Высоты задаются переменными `--controls-h` и `--menu-h` в `styles.css`.

## Распознавание

После снимка приложение само переходит в раздел **«Распознать»**:

- **На фотографии** — рамки найденных ячеек (цвет чередуется по строкам) с подписями.
  Переключатель: «Буквы» / «Брайль» (символ ячейки) / «Рамки» / «Фото» (без разметки).
- **Текстом** — русский текст и та же запись символами Брайля Unicode (⠏⠗⠊⠺⠑⠞).
  Unicode-запись не зависит от языка и пригодится для перевода между стандартами.
- Внизу: «Копировать», «Новый снимок» (возврат к камере), «Озвучить» (синтез речи браузера).
- Результат сохраняется вместе со снимком, повторного распознавания не требуется.
  Распознать старый снимок можно из галереи: снимок → «Распознать».

Как это устроено:

- Модель: Ultralytics YOLO26m, датасет Angelina, вход `[1,3,640,640]`, выход `[1,68,8400]` (4 координаты + 64 класса).
- **Номер класса = битовая маска точек** (бит 0 = точка 1 … бит 5 = точка 6), поэтому символ Брайля — `U+2800 + класс`.
- Текст собирается по правилам русского Брайля: знак заглавной ⠘ (точки 4-5), цифровой знак ⠼ (точки 3-4-5-6) + а…ж → 1…0.
  Шаблоны без русской буквы выводятся символом Брайля.
- Пороги — в `braille.js`: уверенность `confThreshold = 0.2`, перекрытие `iouThreshold = 0.45`.
- ONNX Runtime Web 1.20.1 подключается с CDN jsDelivr. Модель (~41 МБ) и рантайм (~22 МБ) скачиваются при первом
  распознавании и затем берутся из кэша сервис-воркера (работает офлайн).

## Стандарты Брайля

Модель выдаёт клетки (Unicode-Брайль), а текст из них собирается по выбранному стандарту.
Переключатель **RU / EN / 中文** — в карточке текста раздела «Распознать»: смена стандарта мгновенно
переводит тот же снимок заново, без повторного запуска модели; выбор запоминается для снимка.

| Стандарт | Как переводится | Таблица |
|---|---|---|
| Русский | liblouis | `ru-litbrl-detailed.utb` (с заглавными ⠘) |
| English | liblouis, Grade 2 (по умолчанию) или Grade 1 | `en-ueb-g2.ctb` / `en-ueb-g1.ctb` |
| 中文 | `zh.js`: согласная + гласная часть + тон → пиньинь → иероглифы по словарю | — (китайские таблицы liblouis только для прямого перевода) |

**Настройки** (пункт меню «Настройки», хранятся на устройстве): стандарт по умолчанию для новых снимков,
уровень английского (Grade 2 / Grade 1), подбор иероглифов для китайского (вкл/выкл).

Проверено: декодер китайского совпадает с таблицей liblouis `zhcn-g1.ctb` на 97,5% иероглифов
(остальное — расхождения источников в многозначных чтениях); на тестовых фразах с тонами иероглифы
подбираются верно, без тонов — с ошибками на омонимах (их будет исправлять ИИ-агент).

**Ограничение модели:** `braile.onnx` обучена на русском датасете Angelina. На синтетических страницах:
русский — 100% клеток, английский — ~85% (теряется знак заглавной ⠠, точка 6), китайский — ~52%
(теряются одноточечные знаки тонов ⠂ ⠄). Для английского и китайского модель нужно дообучить.

## Язык интерфейса

«Настройки» → «Язык интерфейса»: русский или английский. При первом запуске выбирается по языку браузера.
Все тексты — в `i18n.js` (словари `ru` и `en`); в разметке они подключаются атрибутами
`data-i18n` / `data-i18n-aria`. Чтобы добавить язык, допишите словарь и значение в `UI_LANGS`.

## ИИ-агент: исправление и перевод (RU / EN)

В карточке текста раздела «Распознать» — кнопки **«Исправить»** и **«Перевести → EN/RU»**.

**Окно «Перевод»** (кнопка «Перевести» или пункт меню «Перевод») — отдельный экран:
оригинал → перевод **в том же формате, по строкам** (строк столько же, сколько в оригинале) →
под ним **Брайль целевого языка** (прямой перевод liblouis: RU → русский литературный Брайль,
EN → UEB Grade 2 или Grade 1 по настройке). Кнопки внизу копируют и озвучивают перевод;
↻ — перевести заново. Перевод сохраняется со снимком и обновляется, если текст исправили.

**По умолчанию:** исправление — словарь на устройстве, перевод — Opus-MT на устройстве
(раньше сохранённые настройки переводятся на эти значения один раз).

| | На устройстве | ИИ-агент на сервере |
|---|---|---|
| **Исправление** | Словарь: слово не из словаря → перебор клеток с разницей в одну точку и лишних клеток, проверка через liblouis. Учитывает уверенность модели; слова с 2+ сомнительными клетками не трогает | Языковая модель получает текст, Unicode-Брайль и список сомнительных слов; исправляет только ошибки распознавания |
| **Перевод** | Opus-MT (`Xenova/opus-mt-ru-en`, `opus-mt-en-ru`) через transformers.js, ~110 МБ на направление; каждая строка переводится отдельно | Языковая модель получает массив строк и возвращает массив той же длины (сервер выравнивает, если модель ошиблась) |
| Сеть | Не нужна (после первой загрузки) | Нужна связь с компьютером, где запущен `serve.py` |

- Исправление показывается с подсветкой изменённых слов: **«Принять»** / **«Отклонить»**; после принятия —
  ссылка «Показать исходный». Можно включить «Исправлять автоматически».
- Ключ API хранится только на сервере (`agent/config.json` или переменная окружения), в браузер не попадает.
- `access_token` в `agent/config.json` закрывает агент ключом доступа (поле «Ключ доступа» в настройках) —
  полезно, если сервер доступен в общей сети.
- API: `POST /api/agent` `{"task":"correct","lang":"ru","text":"…","braille":"…","uncertain":[…]}` →
  `{"text","changes":[{"from","to"}]}`; `{"task":"translate","from":"ru","to":"en","text":"строка 1\nстрока 2"}` → `{"text"}` (столько же строк);
  `GET /api/agent/health`.

Проверено на синтетической английской странице (модель верно находит ~85% клеток): словарь исправил
«bn → by», «inofented → invented», «readqs → reads»; слова с несколькими ошибками («andet» вместо «year»)
оставлены агенту.

## Что нужно скачать и настроить

Без настройки работают (это и значения по умолчанию): язык интерфейса, исправление по словарю,
перевод на устройстве — модель Opus-MT скачается с Hugging Face при первом переводе (~110 МБ на
направление, лучше по Wi-Fi). Остальное — по выбору:

### Вариант A. Claude API (лучшее качество, платно по токенам)

1. Зарегистрируйтесь на https://platform.claude.com, пополните баланс, создайте ключ API (Settings → API keys).
2. Скопируйте `agent/config.example.json` → `agent/config.json` (модель по умолчанию — `claude-haiku-5-5`,
   самая быстрая и дешёвая; для сложных текстов — `claude-sonnet-5-5`).
3. Запустите сервер с ключом в переменной окружения:
   - PowerShell: `$env:ANTHROPIC_API_KEY="sk-ant-..."; python serve.py`
   - cmd: `set ANTHROPIC_API_KEY=sk-ant-...` затем `python serve.py`
   (или впишите `"api_key": "sk-ant-..."` в `agent/config.json` — файл исключён из git).
4. В приложении: «Настройки» → «ИИ-агент» → режимы «ИИ-агент на сервере» → «Проверить связь».

### Вариант B. Локальная модель через Ollama (бесплатно, без интернета)

1. Установите Ollama для Windows: https://ollama.com/download
2. Скачайте модель: `ollama pull qwen3:4b` (~2,5 ГБ; на слабом компьютере — `qwen3:1.7b`, качество ниже).
3. Скопируйте `agent/config.ollama.example.json` → `agent/config.json`.
4. Запустите `python serve.py` и проверьте связь в настройках.

Небольшие модели хуже справляются с исправлением русского текста — для демо перевода их достаточно,
для исправления лучше Claude.

### Вариант C. Перевод на устройстве без доступа к Hugging Face

Если телефон не может скачать модель с Hugging Face (или нужна полностью офлайн-версия), положите файлы в проект:

```
web-app/models/Xenova/opus-mt-ru-en/   (и так же opus-mt-en-ru/)
  config.json
  generation_config.json
  tokenizer.json
  tokenizer_config.json
  special_tokens_map.json
  onnx/encoder_model_quantized.onnx          (~52 МБ)
  onnx/decoder_model_merged_quantized.onnx   (~59 МБ)
```

Скачать: `pip install -U huggingface_hub`, затем для каждой модели
`hf download Xenova/opus-mt-ru-en --include "*.json" "onnx/encoder_model_quantized.onnx" "onnx/decoder_model_merged_quantized.onnx" --local-dir models/Xenova/opus-mt-ru-en`
(в старых версиях вместо `hf` — `huggingface-cli`). Либо вручную со страницы https://huggingface.co/Xenova/opus-mt-ru-en/tree/main.

## Сохранение в галерею

Браузер не может писать напрямую в «Фото», поэтому:

- **Android (Chrome)** — после снимка файл `POV_гггг-ММ-дд-ЧЧ-мм-сс-SSS.jpg` скачивается автоматически,
  попадает в «Загрузки» и отображается в Галерее / Google Фото.
- **iPhone (Safari)** — снимок сохраняется в приложении; в просмотре кнопка «Сохранить в галерею» открывает меню
  «Поделиться» → «Сохранить изображение».
- Все снимки также лежат во внутренней галерее приложения (IndexedDB) — оттуда их будет брать модуль распознавания.

## Запуск

Камера в браузере работает только в **защищённом контексте**: `https://…` или `http://localhost`.

```bash
cd web-app
python serve.py              # http://localhost:8000 — проверка на компьютере с веб-камерой
```

Проверка на телефоне — один из вариантов:

1. **USB + Chrome**: включить отладку по USB, на ПК открыть `chrome://inspect/#devices` → Port forwarding `8000 → localhost:8000`,
   на телефоне открыть `http://localhost:8000`.
2. **HTTPS в локальной сети**: создать сертификат (команда в начале `serve.py`), запустить `python serve.py --https`,
   открыть на телефоне `https://<IP-компьютера>:8443` и принять предупреждение о сертификате.
3. **Туннель**: `cloudflared tunnel --url http://localhost:8000` или `ngrok http 8000` — даст публичный HTTPS-адрес.

После открытия в Chrome можно выбрать «Добавить на главный экран» — приложение запустится без панели браузера.

### Публикация на хостинге

Выложите папку `web-app` целиком вместе с `models/braile.onnx`
(нужен HTTPS). После замены модели, liblouis или словаря поменяйте `HEAVY` в `sw.js`, чтобы телефоны скачали новую версию.
На хостинге без Python агент не работает — укажите в «Настройках» адрес компьютера с `serve.py`
(например, `https://192.168.1.10:8443/api/agent`); CORS для `/api/` уже включён.
